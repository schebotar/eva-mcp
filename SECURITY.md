# Безопасность

## Как сообщить об уязвимости

Письмом на **serghei@cebotari.ru**. Публичный issue для этого не подходит: уязвимость
становится известна раньше, чем выйдет исправление.

В письме пригодится:

- версия пакета (`npm view eva-mcp version`);
- имя инструмента и аргументы, на которых воспроизводится дефект;
- ожидаемое и фактическое поведение, минимальный пример.

Ответ приходит в течение нескольких дней. Срок исправления зависит от тяжести:
утечка токена — вне очереди.

## Что считается уязвимостью

- **Утечка `EVA_TOKEN`.** Токен не должен попадать в ответы инструментов, в текст
  ошибок и в логи. Увидели токен в выводе — это уязвимость, сообщайте.
- **Запись там, где ожидалось чтение.** Инструмент меняет данные в EvaTeam, хотя по
  описанию должен только читать.
- **Выход за пределы обмена с EvaTeam.** Чтение файлов помимо `.env` и конфига
  пользователя (`eva-mcp/credentials` в каталоге конфигурации ОС), запись куда-либо, кроме
  создания его шаблона при первом запуске без учётных данных (существующий файл сервер не перезаписывает), выполнение команд, инъекция
  в аргументы запроса.
- **Отказ в обслуживании.** Ответ сервера, который роняет или надолго подвешивает
  процесс.

## Как хранится токен

Токен хранится **открытым текстом** — в переменной окружения, в `.env` или в конфиге
пользователя (`eva-mcp/credentials` в каталоге конфигурации ОС). Шифрования и системного
хранилища ключей нет — так же хранят учётные данные `git` (`~/.git-credentials`) и `aws`
(`~/.aws/credentials`).

- **Linux и macOS:** шаблон создаётся с правами `0600`, каталог `eva-mcp` — `0700`. Если
  файл доступен шире `0600`, сервер предупреждает в stderr при старте; права не меняет.
- **Windows:** режимы POSIX не действуют, файл защищён только правами профиля
  пользователя. Каталог — `%LOCALAPPDATA%`, а не перемещаемый `%APPDATA%`: файл
  не уезжает на файловый сервер с профилем.

Само по себе открытое хранение уязвимостью не считается. Уязвимость — если сервер
выводит токен (см. выше) или создаёт файл с правами шире `0600`.

## Что вне области действия

- **Уязвимости EvaTeam.** Это к вендору — сервер только вызывает его API.
- **Права токена.** Сервер работает с теми правами, что даёт токен. Если токену
  доступно больше, чем нужно, это настройка доступа в EvaTeam, а не дефект сервера.
- **Действия агента по вашей же просьбе.** Инструменты записи (`create_task`,
  `update_task`, `add_comment`, `log_work`, `create_sprint`, `link_tasks`,
  `unlink_tasks`, `link_relation`, `unlink_relation`, `create_doc`, `update_doc`,
  `update_requirement`) меняют живую систему — это их назначение.
