# История изменений

Раздел «До первой публикации» — история до появления пакета в npm. Те версии не
публиковались и тегами не помечались, поэтому дат у них нет, а нумерация осталась
в README тех лет и не всегда совпадала с `package.json`: в манифесте версии шли
0.1.0 → 0.2.0 → 0.4.0 → 0.5.0 → 0.6.0, версий 0.3.0 и 0.7.0 в нём не было.

## 0.8.2 — 2026-09-24

Учётные данные вынесены в конфиг пользователя: сервер работает из любого клиента,
не требуя передавать секрет в конфиге самого клиента.

### Добавлено

- **Цепочка источников `EVA_URL` и `EVA_TOKEN`** (`src/helpers/credentials.ts`):
  переменные окружения процесса → `./.env` в рабочей папке → конфиг пользователя →
  `.env` в корне пакета. Приоритет считается **по каждой переменной отдельно**,
  первый непустой источник побеждает.
- **Конфиг пользователя** — общее умолчание для всех клиентов, dotenv-формат:
  Linux и macOS — `$XDG_CONFIG_HOME/eva-mcp/credentials` (пустой или относительный
  `XDG_CONFIG_HOME` игнорируется → `~/.config/eva-mcp/credentials`),
  Windows — `%LOCALAPPDATA%\eva-mcp\credentials`.
- **Шаблон при первом запуске.** Без учётных данных сервер создаёт файл конфига
  (свой каталог — `0700`, файл — `0600`, существующие файл и каталог не трогаются),
  печатает в stderr путь и что заполнить, и завершается с кодом 1. Второй запуск
  работает. Родительские каталоги вроде `~/.config` создаются с обычными правами.
- **Проверка цепочки** — `scripts/check-credentials.mjs`, часть `npm run check`:
  приоритет попарно и по каждой переменной, пустые значения, путь, шаблон.

### Изменено

- **README — для пользователя**: быстрый старт, подключение клиента, настройка.
  Разработческие разделы переехали в `AGENTS.md`.
- **Источник каждой переменной виден в stderr** при старте — имена источников, не
  значения. В stdout они не попадают никогда: он занят протоколом MCP.

### Исправлено

- **Заметки о выпуске искали веху по имени тега.** Теперь сначала ищется точное
  совпадение с тегом, и только потом короткая форма: у патч-выпуска короткая форма
  совпадает с вехой минора, и заметки прошлого релиза уезжали в заметки нового —
  так вышло с 0.8.1.

### Обновление

Ничего перенастраивать не нужно: переменные окружения по-прежнему имеют наивысший
приоритет. Конфиг пользователя стоит завести, если не хочется повторять секрет
в конфиге каждого клиента.

## 0.8.1 — 2026-09-24

Коррекционный выпуск: страница, созданная через MCP, не попадала в дерево wiki.

### Исправлено

- **`create_doc` писал код родительской страницы не в то поле.** Позицию в дереве навигации
  EvaWiki хранит `tree_parent`, а инструмент заполнял `parent` — раздел страницы, где у страниц
  wiki лежит проект. Страница создавалась и читалась `get_doc`, но в дереве её не было.
- **Вывод выдавал одно поле за другое.** `get_doc` печатал «Родитель: <проект>», а `search_docs`
  показывал проект в колонке «Родитель» — то есть не то, чем фильтрует одноимённый параметр.
  Теперь раздел, место в дереве и тип узла идут отдельными строками.

### Обновление

Страницы, созданные через MCP в 0.8.0, в дерево сами не встанут: у них код страницы лежит
в `parent`, а `tree_parent` пуст. Их нужно один раз перенести в интерфейсе EvaProject —
автоматический перенос не делается.

## 0.8.0 — 2026-09-16

Первый выпуск в npm.

### Добавлено

- **Wiki (EvaWiki, `CmfDocument`)**: `search_docs`, `get_doc`, `create_doc`,
  `update_doc` — поиск, чтение, создание и правка страниц; текст конвертируется
  между HTML и Markdown.
- **Метрики и отчёты** — восемь инструментов, которые раньше были закомментированы
  в `index.ts`: `get_burndown_data`, `get_velocity`, `get_cycle_time`,
  `get_cumulative_flow`, `get_sprint_review`, `get_sprint_retrospective`,
  `get_team_workload`, `get_project_health`.
- **`include_archived`** в `search_sprints`, `search_tasks` и `count_tasks`:
  закрытый спринт уходит в архив вместе с задачами и без этого параметра не виден.
- **Счётчики задач по статусам** в `get_sprint` и `search_sprints` — API отдаёт их
  вместе с остальными полями спринта.
- **`limit` и `offset`** в `search_tasks`, `search_sprints`, `search_requirements`:
  это окно запроса, поэтому в шапке ответа видно и истинное число совпадений
  (`найдено`), и размер окна (`показано`).
- **Проверка репозитория**: `npm run check` (типы плюс состав инструментов против
  документации), `npm run smoke` (собранный сервер поднимается по stdio),
  `npm run probe` (живые вызовы на инстансе).
- **CI** на каждый pull request и на push в `master`: проверка workflow-файлов,
  `check`, `smoke`.

### Изменено

- **Версия сервера берётся из `package.json`**, а не из константы в коде.
- **Выборка задач для метрик и отчётов** идёт серверным фильтром — `lists.code` для
  разреза по спринту, `parent_id` с UUID для разреза по проекту — через общий хелпер
  `src/helpers/scoped-tasks.ts`.
- **`project` убран из `get_burndown_data` и `get_sprint_review`**: разреза задаёт
  спринт, а параметр не влиял на выборку и вводил в заблуждение.
- **Пакет готов к установке**: `bin`, `files: ["dist"]`, `engines`, `prepublishOnly`
  со сборкой; у потребителя запуск сводится к `npx -y eva-mcp`.

### Исправлено

- **Метрики и отчёты тормозили весь инстанс.** Задачи запрашивались без фильтра, и на
  базе порядка 13 700 задач это давало HTTP 502.
- **Отчёты всегда возвращали пусто.** Задачи фильтровались как
  `["parent", "==", <код проекта>]` — такой фильтр молча отдаёт ноль записей.
- **«В работе» в отчётах всегда показывало ноль** на процессах с русскими названиями
  статусов: проверка шла только по подстроке `progress`.
- **Обращение к несуществующему коду** возвращало успешный ответ с пустыми данными;
  теперь сервер явно сообщает, что объект не найден.

## До первой публикации

### 0.7.0 — связи, видимые в интерфейсе

- `link_tasks` и `unlink_tasks` — установка и удаление связей (`depended_tasks`,
  `affected_tasks`, `local_links`, `parent_task`) с merge-семантикой и идемпотентностью.
- `update_task` принимает `depended_tasks`, `affected_tasks`, `local_links`, включая
  пустые массивы для очистки.
- `list_relation_types`, `link_relation`, `unlink_relation` — произвольные связи
  (`CmfRelationOption`), которые видны в EvaProject в разделе «Связи».
- `get_referencing_tasks`: фильтры переведены на пути `*.code`; ошибки логируются,
  а не глушатся.

### 0.6.0 — спринты, комментарии, требования, журнал работ, история

- **Спринты**: `get_sprint`, `search_sprints`, `create_sprint`.
- **Комментарии**: `add_comment` с поддержкой Markdown и вложенных ответов.
- **Требования**: `get_requirement`, `search_requirements`, `update_requirement`
  (правка уходит в черновик текста и публикуется).
- **Журнал работ**: `get_task_worklog`, `log_work`.
- **История статусов**: `get_task_history`.
- **Создание задач**: `create_task`.

### 0.5.0 — иерархические комментарии

- Комментарии в `get_task` показываются деревом: ответы с отступом и префиксом `↳`,
  а не плоским списком.

### 0.4.0 — один `get_task` вместо трёх

- `get_task`, `get_task_comments` и `get_task_full` объединены в `get_task`: он всегда
  возвращает и задачу, и комментарии, и упомянутые задачи.
- В `count_tasks` добавлен `linked_to`.

### 0.3.0 — обратный поиск связей

- `get_referencing_tasks` — какие задачи ссылаются на указанную.
- `get_linked_tasks_batch` — связи для нескольких задач (до 50) одним вызовом.
- Секция «Упомянутые задачи» в ответе `get_task`.
- Фильтр `linked_to` в `search_tasks`.
